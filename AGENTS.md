# Организация рабочего пространства

Для планов и фасадов применяй скилл building-drawings, если он доступен.

- Общие инструменты — `scripts/`. Не помещай сюда координаты и допущения конкретного дома.
- Рабочие файлы — `objects/<адрес>/`. Без адреса назначай следующий свободный номер `Объект-NNN`; не останавливай работу для выяснения адреса.
- Внутри объекта используй `sources/`, `references/`, `models/`, `scripts/`, `output/`.
- Исходники из Temp сохраняй в `sources/`; скрипты не должны зависеть от временных файлов или прежнего пути объекта.
- Объектные скрипты определяют папку проекта относительно своего файла, общие инструменты — относительно корня рабочего пространства.
- При новом объекте обновляй таблицу в README.md. Не приписывай адрес или серию другому скану только из-за соседства в чате.
- Не заменяй существующие результаты другого здания. Допущения храни вместе с результатами объекта, не в корне.
- Архивы скиллов — `skills/`; технические журналы рабочего пространства — `docs/`.

## Замечания из веб-интерфейса

Локальное приложение находится в `review-app/`, запуск — `scripts/start_review.ps1`.

Если пользователь просит исправить сохранённые замечания, ищи `objects/<объект>/review/revision-*/comments.json` и соответствующий `marked-preview.png`. Читай последний относящийся к нужному чертежу набор; не считай тестовые файлы из Temp замечаниями пользователя. `latest-<sha256>.json` указывает последний набор для конкретной версии.

В JSON есть тип действия, комментарий, размер/значение, статус, точки в SVG и CAD, `source_path` и SHA256. Сверь хеш с текущим DXF. Если он отличается, сравни с сохранённым `source.dxf` и заново сопоставь элементы; не переноси координаты на изменённый файл автоматически. Не считай визуальную стрелку точным размером, если пользователь дал числовое значение или другая привязка требует уточнения.

Исправляй модель/объектный скрипт, затем выпускай DXF и предпросмотр. Сохранённую ревизию не изменяй: рядом с новым результатом запиши, какие замечания выполнены и какие остались. В пользовательском интерфейсе быстрые действия создают замечания, а не автоматически редактируют DXF. Браузерный черновик доступен агенту только после сохранения в папку объекта.

## Версии результатов

Выпуски каждого объекта хранятся отдельно: `output/v1/`, `output/v2/` и далее. При новом построении объектный скрипт создаёт следующую версию, не перезаписывая предыдущую. В интерфейсе выбираются версия и DXF; исходники из `sources/` и `references/` доступны в режиме просмотра.

## Создание объекта из веб-интерфейса

Форма «Новый объект» сохраняет ответы и категории исходников в `objects/<идентификатор>/models/brief.json`; загруженные оригиналы записываются в `sources/`. Не выводи пропущенные значения из значений по умолчанию. До построения прочитай бриф вместе с источниками и соблюдай инструкции `building-drawings`.
